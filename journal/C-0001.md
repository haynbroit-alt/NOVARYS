## Échecs et erreurs, conservés

- **`registre-ajout-seul` : ÉCHEC (preuve n°7).** Sur `main`, `INSERT OR REPLACE` réécrit un encaissement, une
  dépense approuvée et une ligne d'audit. Les 291 tests du moteur ne le voyaient pas. Correctif et tests dans
  la PR SOVEREIGN n°9 ; la capacité repassera par `omega run` quand l'épingle du moteur aura avancé.
- **`etat-persistant-a-jour` : ÉCHEC (preuve n°9).** Le dernier état sauvegardé du moteur date du 17/11/2026.
  Depuis le 18/11, le cycle quotidien s'affiche « réussi » sur GitHub en dix secondes sans rien exécuter : son
  garde-fou de confidentialité le bloque parce que le dépôt est public.
- **Fausse alerte due à une sonde, conservée (preuve n°1).** La suite de tests du moteur est sortie en ÉCHEC
  alors qu'elle protège bien le plafond de dépense : la sonde de mutation chargeait parfois le code compilé du
  témoin au lieu du code modifié (même seconde, même taille de fichier). Sonde corrigée, six essais concordants,
  capacité rejouée : preuve n°13. La n°1 reste au registre ; elle ne compte plus, son empreinte ayant changé.
- **Erreur de l'agent, attrapée avant consignation.** La première sonde de `reprise-tache-interrompue`
  sélectionnait un test sans rapport (`-k lease` attrapait « release »). La passe à blanc (`omega verify`) l'a
  montrée en ÉCHEC ; la sonde nomme maintenant ses deux tests.
- **Séries d'essai écartées.** Deux séries de 12 preuves, produites par des versions antérieures de l'outil
  (avant la relecture adverse), n'ont pas été conservées. Elles donnaient les mêmes statuts. Le registre
  commence à la série produite par l'outil tel qu'il est livré.
- **Accès refusés ou indisponibles.** L'exécution du code du dépôt Velyx a été refusée dans cette session ; la
  messagerie du propriétaire demandait une reconnexion. Les actifs hors GitHub restent donc INCONNUS.

## Relecture adverse de l'outil : ce qu'elle a cassé

Un agent indépendant a attaqué l'outil sur une copie, sans voir mes conclusions. Douze défauts reproduits.

Corrigés dans ce cycle, chacun avec un test :

- une preuve PROUVÉE s'obtenait avec une ligne de bilan vide, ou une attaque identique à la commande ;
- un statut retouché à la main puis rescellé passait `omega check` : le statut est maintenant recalculé depuis
  les exécutions consignées ;
- l'empreinte d'une capacité ne couvrait ni ses scripts de sonde, ni son classement, ni le code de ce dépôt :
  modifier une sonde laissait compter l'ancienne preuve ;
- le niveau VALIDÉ s'obtenait en changeant le nom d'acteur : l'outil ne l'attribue plus ;
- un caractère inhabituel dans une sortie (U+2028) rendait le registre illisible ;
- `--base` avec un chemin erroné désactivait le contrôle en silence ;
- un dépôt évalué pouvait être maquillé (fichier masqué à Git, sous-dossier, fichier non suivi) ;
- un processus détaché retenait l'outil bien au-delà du délai ;
- la détection de secrets laissait passer 22 des 24 formats de jetons essayés par le relecteur ; elle couvre
  maintenant seize familles de motifs et retient aussi toute sortie où ressort la valeur d'une variable retirée
  (je n'ai pas rejoué ses 24 formats un à un : neuf sont dans les tests) ;
- des erreurs de type dans le référentiel donnaient une trace d'exécution au lieu d'un message.

Quatre sondes jugées trop faibles ont été durcies : la mutation du plafond a un témoin et vise le bon test ;
l'attaque du registre essaie aussi le rescellement et le retrait ; l'agent tente quatre voies d'encaissement au
lieu de trois ; deux revendications ont été réécrites pour ne dire que ce qui est démontré.

Restent des limites, écrites dans le README : une preuve inventée de bout en bout n'est démasquée que si on la
rejoue ; une commande garde les droits du compte ; les fichiers ignorés par Git ne sont pas contrôlés ; une
expression régulière pathologique dans le référentiel peut bloquer l'outil.
